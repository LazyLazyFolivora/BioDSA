# 推理过程可视化 — 后端需求（BioDSA）

## 问题

当前 agent 的推理过程全部在内部完成，外部无法感知进度。MCP 工具调用者（WeKnora）只能等最终结果，中间没有任何可见的反馈。

agent 的 `generate()` 方法已经在逐步骤地产生输出（`agent_graph.stream()`），但这些输出直接被丢弃了，只留了日志。

## 目标

将 agent 内部的推理过程**外化**为结构化的事件流，让任何前端（包括 WeKnora）都能实时接收并展示 agent 正在发现什么。

---

## 需求

### B1. 推理过程转叙事事件

agent 在运行中会产生大量内部步骤（调用某工具、收到某结果）。后端需要把这些步骤**转译**为人类能理解的叙事事件，而不是原样抛出工具调用日志。

需要产生以下几类事件：

**实体发现** — agent 在某个知识库中找到了一个生物医学实体：
- 事件内容：实体名称、实体类型（基因/药物/疾病/突变/通路/化合物/靶点/文献）、来源知识库
- 示例：`"在基因数据库中发现了 EGFR（表皮生长因子受体）"`

**关系发现** — agent 发现两个实体之间存在某种关联：
- 事件内容：源实体、目标实体、关系类型（靶向/耐药/调控/关联等）、证据来源、证据强弱、是否与已有结论矛盾
- 示例：`"T790M 突变导致 EGFR 对吉非替尼产生耐药（证据强度：高）"`

**阶段切换** — agent 改变了研究策略：
- 事件内容：新阶段名称（规划中/广域检索/深入挖掘/综合分析）、阶段说明
- 示例：`"开始广度检索：同时在基因库、文献库、变异库中搜索"`

**矛盾发现** — agent 发现相互矛盾的证据：
- 事件内容：涉及的两个实体、矛盾描述
- 示例：`"C797S 突变对奥希替尼的影响方向不一致，存在争议"`

**进度更新** — 定期的进度统计：
- 事件内容：已完成步骤数、工具调用次数、各类实体累计发现数量

### B2. 实时事件推送

- 提供一个端点，前端可以建立长连接来接收事件
- 事件按发生顺序实时推送，不等待 agent 结束
- 每次运行（run）有唯一标识，前端通过标识订阅对应的事件流
- 前端可以随时连接（agent 已开始运行后也能接上，不会丢失太多上下文）
- 事件以标准格式序列化，方便前端解析

### B3. 运行标识传递

- MCP 工具被调用时，生成一个唯一的 run_id
- 在 MCP 工具的首包或早期响应中，把这个 run_id 传递给调用方
- 调用方拿到 run_id 后，可以让前端建立事件流连接
- agent 运行结束后，关闭该 run 的事件流

### B4. 允许浏览器跨域连接

- 前端是浏览器（WeKnora 页面），直接连接 BioDSA 的事件端点
- 需要允许来自其他域名的浏览器请求（WeKnora 的域名可能不同于 BioDSA）
- 只开放事件端点即可，其他 MCP 路由不需要跨域

### B5. 不改变现有 MCP 工具接口

- MCP 工具的输入参数、返回格式保持不变
- 已有调用方（WeKnora 的 MCP 客户端）不需要做任何代码修改
- 新增的事件推送机制是附加能力，不影响现有功能

---

## 后端不负责的

- 知识图谱的前端渲染（由 WeKnora 前端负责）
- 用户交互（缩放、点击、悬停等）
- 配色方案和视觉设计
- 事件消费方的连接管理（由前端负责建立和关闭连接）

---

## 验收标准

1. agent 运行时，事件在产生后 500ms 内被推送到订阅者
2. MCP 工具返回结果中包含可识别的 run_id
3. 事件端点可以被浏览器跨域访问
4. 同一个 run 可以被多个前端同时订阅（如多个标签页）
5. agent 运行结束后，事件流正常关闭，前端收到结束信号
6. 现有 MCP 工具调用方（WeKnora）不做任何改动即可正常工作
